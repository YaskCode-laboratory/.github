# Proceso de Ingeniería YaskCode

## Propósito

El Marco de Ingeniería YaskCode convierte un proyecto académico en una experiencia de ingeniería trazable. Su foco es el aprendizaje guiado: cada equipo avanza mediante evidencia, recibe retroalimentación y mejora su solución de forma iterativa.

El proceso no impone una única tecnología ni un único tipo de producto. Ofrece un lenguaje común para proyectos de software, datos, inteligencia artificial y plataformas digitales.

## Ciclo de trabajo

1. **Explorar el problema.** Delimitar contexto, usuarios, necesidad, alcance, restricciones y criterios de valor.
2. **Diseñar la solución.** Formular requisitos, arquitectura, modelo de datos, decisiones técnicas y estrategia de validación.
3. **Planificar la iteración.** Descomponer el trabajo en Issues, priorizarlo en GitHub Projects y acordar una meta verificable.
4. **Construir de forma incremental.** Implementar cambios pequeños, documentados y revisables mediante ramas y pull requests.
5. **Verificar la calidad.** Ejecutar pruebas, controles de integración, revisiones y análisis de seguridad proporcionales al proyecto.
6. **Evaluar y aprender.** Revisar resultados, métricas, riesgos y lecciones; actualizar el siguiente ciclo.
7. **Preparar la comunicación.** Consolidar documentación, autoría, fuentes, evidencias y condiciones de publicación.

Estos momentos se repiten. Un hallazgo de prueba puede modificar el diseño; una revisión arquitectónica puede requerir volver a explorar el problema. La iteración es parte del aprendizaje, no un error del proceso.

## Evidencias mínimas

| Dimensión | Evidencia esperada |
| --- | --- |
| Problema y valor | Propósito, alcance, usuarios y criterios de aceptación. |
| Planificación | Backlog priorizado, iteración y estado visible en GitHub Projects. |
| Diseño | Diagramas, ADRs o decisiones técnicas justificadas. |
| Construcción | Commits comprensibles, ramas de trabajo y pull requests. |
| Verificación | Pruebas, resultados de CI, revisión y hallazgos. |
| Seguridad | Riesgos relevantes, dependencias y medidas adoptadas. |
| Comunicación | README, guía de ejecución, fuentes, créditos y licencia si aplica. |

## Project Passport

El Project Passport es la evidencia integradora del proyecto. Se actualiza durante todo el semestre y debe permitir que otra persona comprenda la evolución de la solución.

Incluye, según la naturaleza del proyecto:

- Identidad, equipo, contexto y objetivo.
- Problema, alcance, requisitos y criterios de aceptación.
- Arquitectura, datos, decisiones y riesgos.
- Backlog, iteraciones y contribuciones relevantes.
- Estrategia y resultados de testing, CI/CD, seguridad y métricas.
- Fuentes, uso de herramientas de IA cuando corresponda, autoría y condiciones de publicación.
- Resultados, limitaciones, lecciones aprendidas y próximos pasos.

## Evaluación del proceso y del producto

La evaluación considera el valor del resultado y la calidad del camino recorrido. Se observa la colaboración, trazabilidad, capacidad de justificación, calidad técnica, gestión del cambio y comunicación responsable. Las rúbricas concretas se definen para cada asignatura o cohorte.

## Apertura posterior al semestre

La privacidad es el estado predeterminado durante el semestre. La posibilidad de apertura se revisa después de la evaluación y requiere, como mínimo, revisión del material, preparación del repositorio, validación de fuentes y dependencias, consentimiento de las personas autoras y definición explícita de licencia o condiciones de uso.
