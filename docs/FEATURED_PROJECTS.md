# Featured Projects

Featured Projects es una selección institucional de proyectos **públicos** de YaskCode Laboratory con valor especial como ejemplos de aprendizaje, ingeniería, experimentación tecnológica o educación abierta.

**Featured Project ≠ mejor estudiante.**

**Featured Project ≠ mejor calificación.**

**Featured Project ≠ proyecto con más GitHub Stars.**
**Featured Project = proyecto seleccionado por su valor como experiencia pública de ingeniería y aprendizaje.**

## Principios de selección

La selección considera de manera proporcional calidad de ingeniería, problema abordado, claridad de propósito, coherencia entre requisitos y solución, arquitectura o enfoque, implementación, testing, seguridad, documentación, trazabilidad, Project Passport, evidencias, aprendizaje generado, comunicación técnica, autoría, preparación para educación abierta y utilidad como referencia para futuras cohortes.

No todos los proyectos tienen que destacar en las mismas dimensiones. No se usa una matriz rígida de puntuaciones: la selección admite diferentes razones cualitativas para destacar un proyecto.

## Elegibilidad

Un proyecto puede considerarse únicamente si:

- terminó su evaluación académica y revisión técnica;
- el repositorio puede hacerse público;
- no contiene secretos y se revisaron datos sensibles;
- existe autoría identificada, consentimiento cuando corresponde y licencia apropiada;
- posee documentación suficiente, Project Passport preparado y contexto académico claro;
- completó el [Publication Readiness Checklist](../templates/PUBLICATION_READINESS_CHECKLIST.md).

El [Project Passport](PROJECT_PASSPORT.md) aporta el contexto y las evidencias del proyecto; Featured Projects no crea documentación paralela ni lo duplica.

## Dimensiones de valor

### Ingeniería

Diseño, arquitectura, implementación, decisiones técnicas y mantenibilidad.

### Calidad y testing

Evidencias de pruebas, CI/CD, verificación, métricas y corrección.

### Documentación y trazabilidad

README, Project Passport, ADR cuando corresponde, fuentes, decisiones y evidencias.

### Seguridad y responsabilidad

Manejo responsable de datos, secretos, dependencias, privacidad e IA.

### Aprendizaje

Capacidad para enseñar procesos, decisiones, experimentos, errores, iteraciones o mejoras.

### Educación abierta

Capacidad para ser comprendido, reutilizado o estudiado responsablemente por otras personas.

Estas dimensiones preparan una base conceptual para futuros reconocimientos técnicos, pero esta V1 no crea badges, iconos ni criterios definitivos.

## Tipos de Featured Project

Un proyecto puede destacarse, cuando corresponda, como:

- Featured Engineering Project;
- Featured Learning Project;
- Featured Open Education Project;
- Featured Technical Experiment;
- Featured Documentation Project.

No se exige que cada proyecto pertenezca a una categoría. Un mismo proyecto puede aportar valor en más de una dimensión, manteniendo una presentación pública sencilla.

## Proceso de selección

**Proyecto finalizado → Publication Readiness → Proyecto público → Revisión para Featured Projects → Selección → Registro en Semester Archive → Presentación pública**

La revisión considera evidencia existente, contexto académico, calidad técnica, documentación, aprendizaje y publicación responsable. El Tech Lead académico puede participar; la decisión final es institucional y documentada. No se automatiza la selección.

La selección puede realizarse al cierre de cada semestre, después de preparar proyectos para publicación o posteriormente si un proyecto adquiere nuevo valor educativo. No se requiere que cada cohorte tenga proyectos seleccionados.

## Relación con Semester Archive y CI/CD

El [Semester Archive](SEMESTER_ARCHIVE.md) conserva la memoria de las cohortes; Featured Projects selecciona algunas experiencias públicas con especial valor educativo o técnico. No todos los proyectos archivados deben ser Featured Projects, ni los Featured Projects deben ser los más populares.

Las ejecuciones de CI/CD pueden aportar evidencia sobre build, testing, calidad, reproducibilidad, Docker y correcciones. Tener CI/CD no convierte automáticamente un proyecto en Featured Project.

## GitHub Stars y reconocimiento comunitario

Las GitHub Stars pueden utilizarse posteriormente como señal pública de interés de la comunidad. No son un criterio obligatorio de elegibilidad, ni sustituyen revisión técnica o evaluación académica, ni son el criterio principal para Featured Projects.

Un proyecto puede ser Featured Project con pocas Stars; un proyecto puede tener muchas Stars sin ser Featured Project. Su relación con reconocimiento comunitario se definirá posteriormente en Community Recognition V1. Esta V1 no implementa conteos, API, votaciones ni selección basada en Stars.

## Reconocimientos técnicos

En el futuro, YaskCode Laboratory podrá establecer reconocimientos verificables relacionados con Engineering Quality, Documentation, Testing, Open Education Ready, Security y Project Passport Complete. No se diseñan badges, SVG, imágenes ni insignias en esta versión.
