# Estándares y principios

## Referentes del laboratorio

YaskCode Laboratory se inspira en estándares y cuerpos de conocimiento reconocidos. Se aplican de manera proporcional a cada proyecto, curso y nivel de experiencia.

| Referente | Aplicación en el laboratorio |
| --- | --- |
| **SWEBOK** | Lenguaje común para áreas de conocimiento de Ingeniería de Software. |
| **ISO/IEC/IEEE 12207** | Comprensión de procesos del ciclo de vida del software. |
| **ISO/IEC/IEEE 29148** | Buenas prácticas para ingeniería de requisitos. |
| **ISO/IEC/IEEE 42010** | Comunicación y justificación de arquitectura. |
| **ISO/IEC/IEEE 29119** | Principios y documentación de pruebas de software. |
| **Familia ISO/IEC 25000 SQuaRE** | Gestión y evaluación de calidad de producto; **ISO/IEC 25010** orienta atributos como adecuación funcional, rendimiento, seguridad, mantenibilidad y usabilidad. |
| **ISO/IEC 15939** | Proceso de medición y uso responsable de métricas como evidencia. |
| **ISO/IEC 27001 y prácticas DevSecOps** | Gestión de riesgos de seguridad y desarrollo responsable. |
| **ISO/IEC 42001** | Sistema de gestión para IA; apoya gobernanza, responsabilidades y mejora continua. |
| **ISO/IEC 23894** | Gestión de riesgos para sistemas de IA. |

Las referencias se usan con sentido crítico. No se pretende certificar proyectos estudiantiles ni exigir documentación innecesaria; se busca comprender qué problema resuelve cada práctica y usarla con rigor adecuado al contexto.

## Principios de calidad

- **Valor y propósito:** toda solución responde a una necesidad delimitada y verificable.
- **Trazabilidad:** requisitos, decisiones, cambios y resultados pueden relacionarse.
- **Calidad integrada:** testing, revisión, seguridad y documentación se incorporan durante el trabajo.
- **Automatización responsable:** CI/CD reduce errores repetibles y aporta evidencia, sin sustituir el juicio técnico.
- **Arquitectura explícita:** las decisiones relevantes se hacen visibles, se justifican y se revisan.
- **Métricas con contexto:** los indicadores informan aprendizaje y mejora; no son un fin ni una medida aislada de desempeño.

## Seguridad, privacidad y ética

La seguridad es una propiedad del proceso. Cada equipo identifica riesgos pertinentes, evita exponer secretos o datos personales, revisa dependencias y documenta medidas relevantes. Con sistemas de IA, se consideran además errores, sesgos, privacidad, trazabilidad de fuentes y supervisión humana.

## Autoría y educación abierta

La autoría reconoce contribuciones reales y acredita fuentes, activos, datos, herramientas y aportes externos. Los proyectos permanecen privados durante el semestre. Una eventual publicación requiere evaluación concluida, revisión técnica y documental, consentimiento, preparación del material y condiciones claras de reutilización.

## Métricas como evidencia

Se seleccionan por su utilidad para decidir: estado del backlog, tiempos de ciclo, resultados de pruebas, cobertura cuando corresponda, incidencias, salud de dependencias, criterios de aceptación y calidad documental. Los números se interpretan junto con el contexto y los aprendizajes del proyecto.
