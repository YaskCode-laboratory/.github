# Reconocimiento de la comunidad

YaskCode Laboratory puede utilizar señales públicas de interacción para observar cómo la comunidad descubre, guarda, consulta o valora proyectos publicados. La primera señal considerada es **⭐ GitHub Stars**.

Una Star expresa interés o intención de guardar o seguir un repositorio; no constituye una revisión académica o técnica formal.

| Concepto | Qué representa |
| --- | --- |
| Evaluación académica | Aprendizaje y cumplimiento académico. |
| YaskCode Recognition | Fortaleza específica basada en evidencia. |
| Featured Project | Selección institucional integral. |
| GitHub Stars | Interés orgánico de la comunidad. |
| Community Recognition | Interpretación institucional de recepción pública. |

**GitHub Stars ≠ calificación.**

**GitHub Stars ≠ calidad técnica certificada.**

**GitHub Stars ≠ Featured Project.**

**GitHub Stars ≠ YaskCode Recognition.**

**GitHub Stars ≠ ranking académico.**

## Principios

### Orgánico

Las Stars deben obtenerse de manera natural. No se incentiva spam, intercambio artificial de Stars ni prácticas engañosas.

### Público

Solo se consideran proyectos que ya sean repositorios públicos y hayan completado su apertura responsable.

### Independiente de la evaluación

Las Stars nunca modifican calificaciones, aprobación, evaluación del estudiante ni evaluación del equipo.

### Contextual

Una cantidad de Stars se interpreta considerando fecha de publicación, tiempo público, visibilidad externa, difusión, tamaño de comunidad y naturaleza del proyecto.

### Transparente

Cuando se publique un número de Stars debe indicarse la fecha de referencia o corte.

## Fecha de corte

El número de GitHub Stars cambia con el tiempo. Un registro debe conservar número de Stars, fecha de consulta, fecha aproximada de publicación cuando esté disponible y período académico.

Ejemplo conceptual:

```text
⭐ 24 GitHub Stars
Fecha de corte: 15 de diciembre de 2026
```

Este ejemplo no representa un proyecto real.

## Comparabilidad

No es apropiado comparar directamente un proyecto publicado hace dos años con uno publicado hace una semana, ni proyectos con audiencias, difusión o naturalezas tecnológicas incomparables. Por ello, las Stars se utilizan primero como indicador descriptivo; no existe una clasificación global de proyectos.

## Community Recognition

Community Recognition es una distinción futura que puede reconocer recepción pública significativa. Podría considerar Stars, forks, reutilización, referencias externas, contribuciones o discusión pública; en V1 solo se documentan conceptualmente las GitHub Stars.

No se otorga automáticamente por alcanzar una cantidad fija de Stars. Una decisión futura considera contexto temporal y evidencia de recepción pública.

## Most Starred Project

Podría existir conceptualmente un reconocimiento como **⭐ Most Starred Project · 2026** cuando el universo comparado sea claro, todos los proyectos sean públicos, haya fecha de corte, período de comparación y métrica verificable. Ejemplos futuros: *Most Starred Project · 2026-I* o *Most Starred Project · 2026*.

No significa mejor proyecto, mejor estudiante, mejor calificación ni mejor calidad técnica. Esta V1 no crea ganadores.

## Sin umbrales en V1

No se definen niveles, umbrales ni milestones automáticos basados en Stars. No se crean badges visuales. Cualquier criterio futuro deberá estudiarse con datos reales y contexto suficiente.

## Relación con Featured Projects y Recognitions

Un [Featured Project](FEATURED_PROJECTS.md) es curaduría institucional por valor técnico y educativo; GitHub Stars son recepción orgánica posterior. Un Featured Project puede tener pocas Stars, y un proyecto con muchas Stars puede no ser Featured Project. Las Stars podrían aparecer posteriormente como contexto en una ficha pública.

Los [YaskCode Recognitions](RECOGNITIONS.md) reflejan fortalezas específicas basadas en evidencia. Las Stars no conceden Engineering Quality, Testing & Quality, Documentation Excellence, Security Practices, Open Education Ready ni Project Passport Complete.

## Relación con Semester Archive

El [Semester Archive](SEMESTER_ARCHIVE.md) podrá mostrar posteriormente recepción pública de proyectos seleccionados, siempre con contexto temporal. Ejemplo conceptual: proyecto publicado en diciembre de 2026, con Featured Project, reconocimientos aplicables, Stars registradas y fecha de corte. No se agregan proyectos ni registros reales en esta V1.

## Automatización futura

En el futuro, GitHub API o GitHub Actions podrían recopilar Stars, forks, fecha de consulta y evolución temporal. No se implementa aquí. Cualquier automatización usará solo información pública, registrará la fecha de consulta, evitará datos personales innecesarios, conservará contexto y no modificará la evaluación académica.

Una evolución posterior podría guardar snapshots: **Stars al publicar → Stars a 30 días → Stars a 90 días → Stars al cierre anual**. Esta V1 no implementa series temporales.

## Comunidad y aprendizaje

La finalidad no es crear una competencia. La recepción comunitaria puede ayudar a identificar proyectos útiles, descubrir recursos educativos, apoyar a futuras cohortes, promover participación, observar qué soluciones generan interés e incentivar documentación y apertura responsable. Las Stars no son un objetivo académico.

## Integración futura con la web

La futura web de YaskCode Laboratory podría mostrar para proyectos públicos período, categoría, Featured Project, YaskCode Recognitions, GitHub Stars, fecha de corte, Project Passport, repositorio y demo cuando exista. Los datos de Stars siempre se mostrarán con contexto temporal. Esta V1 no construye la web.
